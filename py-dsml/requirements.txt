# ---------------------------------------------------------------------------
# COLAB PARITY PINS -- the scientific stack, held to what Google Colab ships.
#
# WHY THESE ARE PINNED AND THE REST ARE NOT. This image is the execution gate
# for the CSC 408 and CSC 509 curricula, and those notebooks run for students
# EXCLUSIVELY in Google Colab. A gate that validates against a different stack is not
# predicting what students see, which is the only thing the gate is for.
#
# These packages arrive UNPINNED from the ancestors -- numpy and pandas from
# py-sci-base, scikit-learn from py-sci-jupyter-ml -- on top of a `:latest`
# base tag. A floating tag on a floating base: the versions moved without
# anyone touching a consuming repo, and nothing recorded that they had.
# Measured 2026-09-22, `ghcr.io/mk-imagine/py-dsml:latest` had gone to
# pandas 3.0.5 / numpy 2.5.3 / scikit-learn 1.9.1 while Colab was still on
# pandas 2.2.3 / numpy 2.1.3 / scikit-learn 1.6.1.
#
# That is not cosmetic. Two measured consequences:
#   * pandas 3 pickles StringDtype with an argument pandas 2.2.3 cannot accept,
#     so any bundle holding a string column raises TypeError on load in Colab.
#   * RandomForest results move across scikit-learn 1.6 -> 1.9 DESPITE a pinned
#     random_state. On one curriculum comparison the seed-to-seed spread went
#     0.0577 -> 0.0772 and the reported margin-to-noise ratio 4.0:1 -> 3.0:1.
#     The published figure would have been one a student could not reproduce.
#
# Pinned here rather than in the ancestors deliberately: Colab parity is a
# CURRICULUM constraint, and imposing it on py-sci-base would force a teaching
# requirement onto every unrelated downstream image. pip resolves this file
# last, so these downgrade whatever the ancestors installed.
#
# HOW TO UPDATE. Do not bump these to chase upstream releases. Re-probe Colab
# (a fresh notebook, `importlib.metadata.version` over this list) and match it.
# Colab is the source of truth; this file is a mirror of it.
# Probed 2026-09-22 against Colab running Python 3.13.15.
# ---------------------------------------------------------------------------
pandas==2.2.3
numpy==2.1.3
scikit-learn==1.6.1
scipy==1.16.3
statsmodels==0.15.0

# sklearn's parallelism backend. Pinned with the rest because thread-pool
# behaviour is one of the ways an ensemble's results can move between
# environments that agree on every library version that gets quoted.
joblib==1.6.0
threadpoolctl==3.6.0

# PyTorch stack, for CSC 509. Pinned to Colab's CPU runtime (googlecolab/
# backend-info pip-freeze.txt, fetched 2026-10-02). torch arrives UNPINNED from
# py-sci-jupyter-torch and had drifted to 2.14.0 / torchvision 0.29.0 while
# Colab ships 2.11.0 / 0.26.0 -- the same floating-base drift described above.
#
# The `+cpu` local version is what makes the extra index safe here. Those
# builds exist only on the PyTorch CPU index, so a missing or wrong index fails
# the install loudly instead of resolving PyPI's CUDA build of the same version
# (the reason py-torch-cuda replaces the index outright). Colab's GPU runtime
# ships the cu130 builds of the same versions; this image is CPU-only, so CPU
# vs. GPU numeric differences are reconciled by tolerance in the consuming
# repo's gate, not here.
#
# tensorboard is not in any ancestor. Colab preinstalls it, and CSC 509 logs
# training runs with torch.utils.tensorboard.SummaryWriter; without it every
# such notebook fails at import in the gate while working for students.
--extra-index-url https://download.pytorch.org/whl/cpu
torch==2.11.0+cpu
torchvision==0.26.0+cpu
torchaudio==2.11.0+cpu
tensorboard==2.21.0
tensorboard-data-server==0.7.2

# Reading the curriculum's .xlsx sources.
openpyxl==3.1.5

# Programmatic notebook execution (headless build/verify pipelines)
nbclient
nbformat

# Plotting
matplotlib==3.10.0
seaborn==0.13.2

# Serialization beyond pickle (lambdas, closures, model bundles)
dill==0.4.1

# Verification cells and build-script tests
pytest

# Figure measurement -- reading back the PNGs that rsvg-convert produces -- and,
# for CSC 509, decoding every training image a torchvision transform sees. It
# arrives as a matplotlib/torchvision dependency but is declared because figure
# scripts import it directly. Pinned to Colab (11.3.0; it had floated to 12.3.0)
# because image decoding sits directly under computed results in CSC 509.
pillow==11.3.0

# Fetching figures from Google Drive. The curriculum's display_image() helper
# downloads each embedded SVG with gdown. Colab preinstalls it, so without it
# here the gate stores "gdown is not installed" in place of every figure, and
# stops matching what students see. Unpinned like nbclient and pytest: it only
# moves bytes and never touches a computed result, and the 2026-09-22 Colab
# probe did not record its version. Re-probe and pin it if that ever matters.
gdown

# Perceptual image hashing. Backs the image-dedup leakage screen: near-duplicate
# images split across train and test inflate scores without any model learning
# anything, and exact-hash comparison misses them because a resize or
# requantization changes every byte.
imagehash
